# Schedule 214Р — iOS companion + WidgetKit

Это минимальная нативная оболочка для системного iOS-виджета. Основное приложение остаётся Next.js/PWA.

## Preview API

Пока PR #81 не смержен, companion и WidgetKit направлены на preview alias ветки:

`https://schedule-git-feature-ios-widget-ivanio.vercel.app`

После merge этот адрес нужно вернуть на production URL.

## Что уже есть

- приложение сразу открывает существующий веб-интерфейс внутри WKWebView;
- авторизация и настройки выполняются прямо внутри iOS-приложения;
- сопряжение с текущим веб-профилем через одноразовый deep link, который WKWebView перехватывает внутри приложения;
- отдельный read-only widget token вместо personId;
- Small и Medium Home Screen widgets;
- Lock Screen варианты accessoryRectangular и accessoryInline;
- timeline на начало и конец событий без сетевого запроса каждую минуту;
- кэш последней успешной сводки в App Group;
- переход из companion-приложения в основное расписание.

## Запуск

1. Установи Xcode 26+ и XcodeGen.
2. В терминале:

   ```bash
   cd ios
   xcodegen generate
   open Schedule214.xcodeproj
   ```

3. В Xcode выбери свою Development Team для targets `Schedule214` и `ScheduleWidget`.
4. Если Apple Developer Portal не позволяет App Group `group.com.schedule214.shared`, замени его одинаково в:
   - `Schedule214/Schedule214.entitlements`
   - `ScheduleWidget/ScheduleWidget.entitlements`
   - `Shared/WidgetEnvironment.swift`
5. Запусти приложение на iPhone — оно сразу откроет веб-интерфейс на странице настроек.
6. Войди в профиль прямо внутри приложения и нажми **Приложение → iOS-виджет → Подключить iPhone**.
7. WKWebView перехватит deep link и передаст одноразовый код нативной части без перехода в Safari.
8. После успешного подключения добавь виджет «214Р · Мой день» через системную галерею виджетов.

## Одна Live Activity на день

Одна карточка хранит расписание дня целиком; её ID зависит только от профиля и даты.
При смене пары, перерыва и завершении дня обновляется содержимое той же Activity.
Очередь отдельных Activity на каждую пару удалена. При обновлении старые карточки
прежней реализации закрываются. Закрытие пользователем относится ко всему дню.

- До первой пары — отсчёт до её начала.
- Во время пары — название, преподаватель/аудитория, крупный таймер справа,
  прогресс и штриховая отметка пятиминутного перерыва на 40–45-й минутах.
- Между парами — «Сейчас перерыв» и отсчёт до следующей.
- После последнего занятия — «На сегодня всё».
- Часы показываются, если осталось больше 60 минут.
- Тема, градиент и акцент берутся из оформления профиля.

В iOS 26+ можно заранее запланировать одну карточку на следующий день (по началу
первой пары). Pending-карточка не создаётся на каждое занятие. На iOS 17–25
карточка дня запускается при открытии приложения. Расписание читается в Europe/Minsk.

Контроллер обновляет существующую Activity каждые пять секунд, пока приложение
активно, и при возвращении в приложение. Сеть обновляется раз в минуту.
В snapshot находится весь день, поэтому при системной перерисовке нужная пара
выбирается локально. `staleDate` отмечает ближайшую границу расписания.

### Ограничения ActivityKit

Live Activities не поддерживают WidgetKit timeline. Без APNs и при приостановленном
приложении нельзя гарантировать обновление на каждой границе пары: iOS определяет
момент перерисовки. `staleDate` не является повторяющимся фоновым таймером.
Постоянство ID не снимает системный предел активности около восьми часов.
Приложение не создаёт дополнительные карточки на каждую пару для обхода ограничения.

Состояние и атрибуты ограничены 4 KB; профиль и оформление в дневном snapshot
хранятся однократно. При превышении лимита выводится ошибка; занятия не обрезаются.
Отключение профиля очищает старую Activity при синхронизации. Истёкшие дневные карточки не создаются повторно.

## WebView на весь экран

WebView занимает всю площадь окна, включая системные safe areas. Автоматические
нативные content insets выключены, чтобы не дублировать отступы сайта.
В нативной оболочке viewport использует `viewport-fit=cover`, а внутренние отступы
контента и нижней навигации учитывают вырез экрана и домашний индикатор через CSS env().
Keyboard safe area сохраняется: клавиатура не перекрывает нижнюю часть WebView.

## Проверка

GitHub Actions запускает Foundation-тесты расписания дня и собирает сохранённый
Xcode-проект с embedded WidgetKit extension. Тесты проверяют постоянство дневного ID,
выбор текущей пары из общего snapshot, перерывы, конец дня, отмены, переносы,
совместимость старых данных и очистку вчерашнего расписания.

В Xcode есть превью светлой, тёмной, завершённой карточки и перерыва.
На iPhone нужно проверить: отсутствие пустых полос WebView в портретной и альбомной
ориентации, работу клавиатуры и неизменный ID Activity при переходах между парами.

## Репетиции, индивидуальные и закрытие через час

Одна дневная карточка включает пары, приглашённые репетиции и индивидуальные из
персонального feed. Для репетиций используются их цвет и иконка театра, для
индивидуальных — собственный цвет и иконка человека. Пятиминутный штриховой перерыв
показывается только внутри обычной пары. При пересечении событий основным становится
последнее начавшееся из текущих; конец дня определяется максимальным окончанием всех.

`dismissalDate` = окончание последнего активного события + один час. После завершения
дня приложение вызывает `end(..., dismissalPolicy: .after(dismissalDate))`: итоговая
карточка остаётся на экране блокировки до этого времени даже при последующем сворачивании.
Dynamic Island закрывается сразу при end() — это системное поведение, а не таймер на час.
Если приложение всё время спит и не выполнило end(), точное удаление без APNs
не гарантируется. При следующей синхронизации просроченная карточка удаляется сразу.
Системный лимит около восьми часов может закончить Activity раньше.

Факт завершения сохраняется отдельно, чтобы отсутствие завершённой Activity в массиве
activities не запускало новую карточку каждые пять секунд. Час после поздней репетиции
может переходить через полночь; отменённые события не продлевают этот срок.
