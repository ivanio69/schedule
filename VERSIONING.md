# Версии приложения

Приложение использует схему `major.minor.hotfix`.

## Правила

### Актуальная схема — начиная с PR #46

Начиная с PR #46 версия считается **от последней опубликованной версии в целевой ветке**, а не из номера PR.

- Обычный PR повышает `minor` на 1 и сбрасывает hotfix в 0.
  - `3.7.1` → `3.8.0`
  - `3.8.2` → `3.9.0`
- Hotfix повышает только третье число.
  - `3.8.0` → `3.8.1`
  - `3.8.1` → `3.8.2`
- Hotfix **не расходует minor-версию**. Поэтому после `3.7.1` следующий обычный PR — `3.8.0`, независимо от номера PR.
- Незамерженный или закрытый PR больше не создаёт пропуск в minor-нумерации: следующий релиз считается от фактической версии в `main`.
- Исключение — **явная консолидация нескольких готовых minor-PR в один релиз по решению владельца проекта**. В таком PR в `version.json` указывается `consolidatesPrs` со списком superseded PR. Итоговый minor увеличивается на количество этих PR плюс один для самого релизного PR. Например, `4.3.0` + три консолидируемых PR → `4.7.0`.
- Major повышается только при очень крупном наборе изменений или по явному решению владельца проекта:
  - `3.x.y` → `4.0.0`;
  - PR major-релиза становится новым `majorBasePr`.
- Для обычного minor и hotfix значение `majorBasePr` сохраняется от текущей major-линии.
- Поле `pr` по-прежнему содержит номер текущего PR, но больше не участвует в вычислении minor.

### Dev-сборки

- Любой коммит вне `main` получает dev-номер целевого релиза: `3.8.0.dev1`, `3.8.0.dev2` и т. д.
- Заголовок каждого коммита начинается с версии в квадратных скобках, например: `[3.8.0.dev2] Fix notification counter`.
- Поле `dev` в `version.json` равно количеству коммитов текущего PR.
- В `main` dev-суффикс скрывается: preview показывает `3.8.0.devN`, production — `3.8.0`.
- `package.json` и корневая версия в `package-lock.json` совпадают с `release`.

## История до PR #46

Исторические версии не переписываются. До PR #46 minor был привязан к номеру PR относительно `majorBasePr`, из-за чего hotfix-PR мог создавать пропуск в следующей minor-версии.

Зафиксированная точка перехода:
- PR #45 → `3.7.1`
- PR #46 → `3.8.0`

## Changelog

Пользовательский changelog хранится в `lib/app-version.ts` и показывается только в центре уведомлений на дашборде. Для changelog не используется Web Push.

В changelog попадают только версии, которые реально опубликованы.
