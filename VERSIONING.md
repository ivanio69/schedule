# Версии приложения

Приложение использует схему `major.minor.hotfix`.

## Правила

- Нумерация начинается со второй мажорной версии.
- PR #25 закреплён как `2.1.0`. Для текущей major-линии 2 обычный PR получает minor по формуле `PR - 24`: #34 → `2.10.0`, #35 → `2.11.0`.
- Номер резервируется самим PR. Если PR не смержен, версия может быть пропущена в опубликованной истории.
- Каждый обычный PR — новая minor-версия.
- Major повышается только при очень крупном наборе изменений или по явному решению владельца проекта. Major-релиз имеет вид `3.0.0`; номер его PR становится новой точкой отсчёта для minor.
- Hotfix — явное исключение для исправления уже опубликованной версии. Он увеличивает третье число: `2.11.1`, `2.11.2` и т. д.
- Любой коммит вне `main` получает dev-номер целевого релиза: `2.11.0.dev1`, `2.11.0.dev2` и т. д.
- Заголовок каждого такого коммита начинается с версии в квадратных скобках, например: `[2.11.0.dev2] Fix notification counter`.
- Поле `dev` в `version.json` равно количеству коммитов текущего PR и увеличивается на каждом новом коммите.
- В `main` dev-суффикс автоматически скрывается: preview показывает `2.11.0.devN`, production — `2.11.0`.
- `package.json` и корневая версия в `package-lock.json` совпадают с release-версией.

## Changelog

Пользовательский changelog хранится в `lib/app-version.ts` и показывается только в центре уведомлений на дашборде. Для changelog не используется Web Push.

В changelog попадают только версии, которые реально опубликованы. Незамерженные/отменённые PR могут оставлять пропуски в номерах.
